# SAMMS — نظام إدارة أجهزة تقنية المعلومات وطلبات الصيانة
### Smart Asset & Maintenance Management System

نظام ويب ثنائي اللغة (عربي / إنجليزي) لتسجيل أجهزة تقنية المعلومات، وإدارة طلبات الصيانة من الإنشاء حتى الإغلاق، وحفظ سجل الصيانة الكامل لكل جهاز، وعرض مؤشرات الأداء والتقارير الإدارية.

**الفكرة المحورية:** النظام السابق كان يدير *الطلبات* لا *الأجهزة* — كل تذكرة تُفتح وتُغلق ثم تختفي، فلا يتراكم شيء في ملف الجهاز. هنا الجهاز هو المحور: كل طلب وكل عملية صيانة تُضاف إلى تاريخه، فيتحوّل تيار التذاكر المنفصلة إلى سجل يُبنى عليه قرار الإصلاح أو الاستبدال.

> **نظام مقترح** بُني كمشروع شخصي بناءً على فجوة لوحظت أثناء التدريب التعاوني.
> جميع البيانات في هذا المستودع **وهمية بالكامل** ولا تمثل أي جهة حقيقية.

## المشكلة التي يحلّها

| قبل | بعد |
|---|---|
| لا يوجد سجل واضح لجميع الأجهزة | سجل إلكتروني مركزي لكل جهاز |
| يصعب معرفة تاريخ آخر صيانة | يظهر مباشرة في صفحة الجهاز |
| لا يمكن معرفة عدد مرات صيانة الجهاز | عدّاد في صفحة الجهاز + تقرير أكثر الأجهزة أعطالاً |
| لا يُعرف أي عطل يتكرر على جهاز بعينه | تصنيف لكل عطل + توزيع بياني في صفحة الجهاز |
| لا يُفرَّق بين تاريخ الشراء وتاريخ التسليم | حقلان منفصلان لكل جهاز |
| إدخال سجل الأجهزة الأولي يدوياً | استيراد دفعة واحدة من ملف Excel مع معاينة قبل التنفيذ |
| لا يوجد سجل متكامل للصيانة السابقة | سجل صيانة كامل قابل للفلترة والتصدير |
| صعوبة استخراج التقارير | سبعة تقارير جاهزة مع تصدير Excel و CSV |
| لا توجد لوحة مؤشرات | لوحة تتغيّر حسب دور المستخدم |

## التقنيات

| الطبقة | الأداة |
|---|---|
| الواجهة | HTML / CSS مخصص، يدعم RTL و LTR |
| الخادم | PHP 8 |
| قاعدة البيانات | MySQL (PDO + Prepared Statements) |
| بيئة التشغيل | WAMP / XAMPP |

بدون أي إطار عمل أو مكتبة خارجية. الاعتماد الخارجي الوحيد هو خطوط Google Fonts، ويعمل النظام بدونها على خطوط النظام.

## التشغيل محلياً

1. تشغيل خادم محلي (WAMP أو XAMPP) والتأكد من عمل Apache و MySQL.
2. نسخ مجلد المشروع إلى مجلد الجذر — `C:\wamp64\www\samms` مثلاً.
3. استيراد `database/samms_db.sql` عبر phpMyAdmin أو من سطر الأوامر.
4. فتح `http://localhost/samms` في المتصفح.

إعدادات الاتصال في `config/database.php` — وهو الملف الوحيد الذي يتغيّر عند النقل لاستضافة حقيقية.

## سير العمل

```
الموظف ينشئ طلباً                    → New
تقنية المعلومات تستلمه               → InProgress   (حالة الجهاز ← تحت الصيانة)
تسجيل عملية أو أكثر في سجل الصيانة
إغلاق الطلب                          → Completed    (حالة الجهاز ← نشط)
أو يلغيه صاحبه قبل الاستلام          → Cancelled
```

كل انتقال يُسجَّل في `RequestStatusLog` مع المنفّذ ووقت التنفيذ، وأي انتقال غير مسموح يُرفض من الخادم.

## ثنائية اللغة

- زر تبديل في كل صفحة، واللغة تُحفظ في الجلسة وكوكي لمدة سنة.
- اتجاه الصفحة (`dir`) يتبدّل تلقائياً بين RTL و LTR.
- **الواجهة** مترجمة عبر `lang/ar.php` و `lang/en.php` (228 مفتاحاً في كل ملف).
- **البيانات** مترجمة عبر أعمدة `‎*En` في قاعدة البيانات (`DeviceNameEn`, `LocationEn`, `ProblemDescriptionEn`, `ActionTakenEn`, `DepartmentEn`, `FullNameEn`).
- إذا كان العمود الإنجليزي فارغاً — كما في السجلات التي يدخلها المستخدمون لاحقاً — يعرض النظام النص العربي بدلاً من خانة فارغة.

## قاعدة البيانات

خمسة جداول: `Users` · `Assets` · `MaintenanceRequests` · `Maintenance` · `RequestStatusLog`

ستة قرارات تصميمية تستحق الذكر:

1. **`Assets.AssignedUserID` مفتاح خارجي** بدل تخزين اسم الموظف نصاً — يمنع تضارب البيانات عند تغيّر الاسم.
2. **`Request → Maintenance` علاقة One-to-Many** لا One-to-One — الطلب الواحد قد يحتاج أكثر من زيارة، وهذا واقع فعلي في البيانات (الطلب رقم 3 فيه عمليتان).
3. **`RequestStatusLog` جدول مستقل** — بدونه يستحيل حساب زمن الاستجابة أو بناء تقرير أداء الفنيين.
4. **`FaultType` تصنيف مغلق للعطل** إلى جانب الوصف الحر — الوصف يشرح الحادثة الواحدة، لكن السؤال "أي عطل يتكرر على هذا الجهاز؟" يحتاج قيمة قابلة للتجميع. النص الحر لا يُعَدّ: *"الطابعة تحشر الورق"* و *"نفس مشكلة الانحشار رجعت"* نصّان مختلفان لعطل واحد.
5. **`ON DELETE RESTRICT` لا `CASCADE`** على علاقة الجهاز بطلباته — الحذف المتسلسل يمحو تاريخ الجهاز كاملاً، وهو نقيض الغرض من النظام. القاعدة نفسها ترفض الحذف، والواجهة تعرض **استبعاد من الخدمة** (`Retired`) بدلاً منه، فيختفي الجهاز من التشغيل ويبقى سجله للتقارير.
6. **`AssignedDate` منفصل عن `PurchaseDate`** — الجهاز قد يُشترى ويبقى في المخزن أشهراً قبل تسليمه، وعمر الاستخدام هو ما يفسّر الأعطال لا عمر الشراء.

## الأمان

- `password_hash` / `password_verify` (bcrypt) — لا تُخزَّن كلمات المرور نصاً
- Prepared Statements في كل استعلام، بدون استثناء
- تهريب كل المخرجات عبر `htmlspecialchars`
- رمز CSRF في كل نموذج، ويُرفض الطلب عند عدم تطابقه
- `session_regenerate_id` بعد تسجيل الدخول
- رسالة دخول موحّدة للاسم والمرور الخاطئين حتى لا تُكشف أسماء المستخدمين الموجودة
- التحقق من ملكية السجل: الموظف لا يفتح جهاز أو طلب غيره
- تقييد إعادة التوجيه في تبديل اللغة على صفحات المشروع فقط

## استيراد الأجهزة

يقرأ النظام ملفات **.xlsx** مباشرة و **.csv**، ويعرض معاينة قبل التنفيذ توضّح لكل صف: هل سيُضاف أم يُحدَّث أم مرفوض ولماذا. رقم الأصل هو المفتاح — الموجود يُحدَّث والجديد يُضاف. يقبل قيم النوع والحالة بالعربية أو الإنجليزية، ويحوّل تواريخ Excel التسلسلية تلقائياً.

قارئ xlsx وكاتبه مكتوبان بـ PHP خالص دون مكتبات، ودون الاعتماد على إضافات `mbstring` أو `simplexml` — يعملان على أي تنصيب PHP.

## التقارير

لكل تقرير زرّا تصدير:

- **Excel (.xlsx)** — الخيار الموصى به. يُبنى بـ PHP خالص دون مكتبات خارجية (xlsx أرشيف ZIP يضم ملفات XML بترميز UTF-8)، فلا يوجد أي التباس في الترميز أو فاصل الأعمدة. صف العناوين مثبّت وبخط عريض، مع فلتر تلقائي، واتجاه الورقة يتبع لغة الواجهة، والأرقام تُكتب كأرقام قابلة للجمع لا كنصوص.
- **CSV** — ملف قياسي بترميز UTF-8 مع BOM، مخصص للاستيراد إلى أنظمة أو أدوات تحليل أخرى.

سبب وجود الاثنين: صيغة CSV لا تحمل معلومة الفاصل داخلها، و Excel يستنتجه من إعداد "فاصل القائمة" في ويندوز — وهو فاصلة منقوطة في الإعدادات العربية. لذلك يظهر ملف CSV السليم في عمود واحد على تلك الأجهزة، بينما xlsx يعمل في كل الحالات.

التقارير:

1. جميع الأجهزة
2. الأجهزة تحت الصيانة
3. سجل الصيانة
4. أكثر الأجهزة تعرضاً للأعطال — مع تسمية العطل الأكثر تكراراً على كل جهاز
5. عدد طلبات الصيانة حسب الشهر
6. الأعطال حسب النوع — وعدد الأجهزة المتأثرة بكل نوع
7. أداء موظفي تقنية المعلومات — عدد الطلبات، ومتوسط زمن الاستلام والإغلاق بالساعات
